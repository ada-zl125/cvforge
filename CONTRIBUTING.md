# Contribution Guide

Thank you for contributing to CVForge. Please discuss the proposed work before starting implementation.

## Create an Issue

1. Search existing issues to avoid duplicate work.
2. Create an issue with one concise and clear sentence as the title.
3. Describe the problem, expected outcome, and relevant context.
4. Discuss the scope and approach with the maintainers.
5. Start implementation after the scope is agreed.

## Implement the Change

1. Fork the repository.
2. Create a focused branch from the `dev` branch.
3. Keep the implementation limited to the agreed issue.
4. Follow the existing code style and project structure.
5. Add or update tests when behavior changes.
6. Update documentation when the change affects users or contributors.
7. Run linting, type checking, tests, and the production build.

## Submit a Pull Request

1. Push the completed branch to your fork.
2. Open a Pull Request against the `dev` branch.
3. Reference the related issue.
4. Provide a concise summary and explain how the change was verified.
5. Keep unrelated changes out of the Pull Request.
6. Respond to review feedback and keep the branch current.

## Contribution Standards

1. Write clear and maintainable code.
2. Use concise English for code comments and documentation.
3. Preserve existing behavior and interface unless the issue requires a change.
4. Prefer established project patterns and dependencies.
5. Never include credentials, private data, or generated secrets.
